Day 1 · 引用这条主线

每张卡都是「为什么需要它 → 生活比方 → 能跑的短例子 → 新手常错 → 一句话结论」。先看结论，再读代码，不要背。

1引用：同一个箱子又贴了一张纸条

没有它会怎样：C 里想让函数改外面的变量，只能传指针——调用处写 &、函数里写 *，还得随时防着空指针。引用就是给 a 那口箱子再贴一张写着 r 的纸条：写起来跟普通变量一样，改的却是同一口箱子。

int a = 10;
int& r = a;      // 给 a 那口箱子再贴一张纸条 r

r = 99;
std::cout << a;  // 输出：99（改 r 就是改 a）

int b = 20;
r = b;           // 把 b 里的 20 倒进 r 管的箱子
                 // 结果：a = 20，b 还是 20

// int& bad;    // 编译报错：error: 'bad' declared as reference but not initialized
  • 为什么必须当场贴：引用出生时就得绑到一口真实的箱子，之后不能换绑——这正是它比指针安全的地方。
  • 贴了撕不掉：r = b; 是"倒东西"，不是"换箱子"。想换目标只能用指针。
  • 没有空引用：可能没有箱子时用指针 + nullptr（Day 2 卡 8 细讲）。

记住这句就行：引用不是新箱子，是同一口箱子上的第二张纸条。

术语对照：正式叫「引用（reference）」，教材上的准确说法是"变量的别名，不额外占用存储空间"。

2三种 swap：抄一份 / 递门牌号 / 递原件

没有它会怎样：新手最常写的 swap1 是值传递，看着换了，函数一结束外面纹丝不动——这就是"我明明改了怎么没反应"。想让函数真把外面两个箱子互换，必须把原件递进去。

void swap1(int x, int y) { int t = x; x = y; y = t; }        // 复印件
void swap2(int* x, int* y) { int t = *x; *x = *y; *y = t; }  // 门牌号
void swap3(int& x, int& y) { int t = x; x = y; y = t; }      // 原件

int main() {
    int m = 1, n = 2;
    swap1(m, n);     std::cout << m << " " << n;  // 输出：1 2（没换）
    swap2(&m, &n);    std::cout << m << " " << n;  // 输出：2 1
    swap3(m, n);     std::cout << m << " " << n;  // 输出：1 2（又换回来）
}

// swap2(m, n);   // 编译报错：error: invalid conversion from 'int' to 'int*'
  • 为什么值传递改不到：参数是复印出来的，函数一结束复印件就扔了，你的箱子没动过。
  • 指针能改，但要干三件事：调用写 &、函数里写 *、还得先判空。漏一个就编译不过或运行崩。
  • 什么时候非用指针不可：读写寄存器——硬件那边没有箱子给你贴纸条，只有一个地址（如 0x40020000），只能拿门牌号去找。

记住这句就行：互换两个变量直接写引用版，别自己折腾门牌号。

术语对照：这三个版本依次叫「值传递」「地址传递（指针）」「引用传递（pass by reference）」。

3const T&：把原件递给他看，但不许改

没有它会怎样：传 std::string 这种大对象时，值传递每次调用都复印一整串字符，又慢又费内存；只加引用，函数又能顺手把你的东西改了。const 类型& 就是把原件递过去看，再贴一张"不许改"的封条。

void show(const std::string& s) {  // 递原件 + 贴封条
    // s += "!";   // 编译报错：error: passing 'const std::string' as 'this' argument discards qualifiers
    std::cout << s;   // 只能看
}

int main() {
    std::string name = "Tom";
    show(name);          // 不复印，直接看 name 那口箱子，输出：Tom
    const int& r = 10;   // 可以：临时箱子也能贴封条
    // int& bad = 10;    // 编译报错：error: binding reference of type 'int&' to 'const int' discards qualifiers
}
  • 三种写法一条线：值传递 = 复印；T& = 不复印但能改；const T& = 不复印也不能改。
  • 只看看、不打算改的大参数，一律写 const 类型&，这是团队里最常见的函数签名。
  • 报错关键词：discards qualifiers 就是"你把封条撕了"，看到它先想 const。

记住这句就行：只看看、不打算改的大东西，参数就写成 const 类型&。

术语对照：正式叫「常量引用」，作用是不拷贝、不可修改，常用于函数形参。

4cout、endl、::：箭头、"冲水"和"谁家的"

没有它会怎样：printf 要手写 %d、%f，类型和格式符对不上就打出乱码甚至崩；cout 让编译器自己认类型。箭头朝右把东西塞进屏幕，endl 是换行 + 冲水，:: 读作"谁家的"。

int a = 0;
std::cout << "请输入：";     // 输出：请输入：
std::cin  >> a;              // 键盘输入 5

std::cout << a << '\n';        // 输出：5（只换行，快）
std::cout << a << std::endl;    // 输出：5（换行 + 立刻冲出去）

// cout << a;                 // 编译报错：error: 'cout' was not declared in this scope
                               // 忘了写 std:: 或 using namespace std;
  • endl 是换行 + 冲水：冲水 = 把攒在缓冲区里的字立刻推出去；'\n' 只换行，攒够了一起走。
  • 串口为什么用 '\n'：每行都冲一次水，等于每行都等一次硬件，几十行下来明显拖时间。
  • :: 读作"谁家的"：std::cout 是标准库那家的；只写 ::a 是全局那个 a。

记住这句就行：箭头朝哪儿东西就往哪儿走；endl 多了个冲水；:: 就是在说"谁家的"。

术语对照：std::cout 是「标准输出流对象」，endl 是「换行并刷新缓冲区」，:: 是「作用域解析运算符」。

5命名空间：给名字加个"谁家的"

没有它会怎样：两个库都提供 log()，C 里只能改名或加前缀，越写越长。命名空间就是给名字分家：A::log 和 B::log 各叫各的，互不打架。

namespace A { int a = 1; }
namespace B { int a = 2; }

std::cout << A::a;   // 输出：1
std::cout << B::a;   // 输出：2

using namespace A;
using namespace B;
// a = 3;            // 编译报错：error: reference to 'a' is ambiguous

using A::a;          // 只搬 A 家的 a，二义性消失
a = 3;               // 改的是 A::a
  • 为什么写全名最保险：using namespace 把两家东西倒在同一张桌子上，一旦重名，编译器不替你猜。
  • 头文件里别写 using namespace：会把"污染"带给所有 include 它的文件，工程大了很难查。
  • 没名字的家：namespace { int x; } 只在本文件可见，效果跟 static 一样（Day 2 卡 15）。

记住这句就行：名字撞了就写 :: 说清楚是谁家的。

术语对照：正式叫「命名空间（namespace）」，没名字的那个用「内部链接」来描述。

6返回引用：别把拆掉的房子的门牌号给别人

没有它会怎样：返回引用能省一次拷贝，但函数里临时造的箱子，函数一结束就拆房。把它的引用交出去，别人拿到的是作废的门牌号——这次刚好没被盖住，不代表下次还能开门。

int g = 0;
int& getG() { return g; }          // 安全：全局箱子一直在
static int s = 5;
int& getS() { return s; }          // 安全：static 箱子活到程序结束
void fill(int& out) { out = 42; }   // 安全：调用者自己的箱子

int& bad() { int x = 1; return x; }  // 危险：x 随函数结束销毁

int main() {
    int& r = bad();
    std::cout << r;   // 可能打印 1，也可能乱码/崩溃：行为未定义
}
// 编译器通常只给警告：warning: reference to local variable 'x' returned
  • 为什么"有时看着能跑"：栈上那块内存还没被别的函数盖掉；换编译器、换优化等级就现原形。
  • 能安全返回的只有三种：全局变量、static 变量、调用者自己传进来的引用/指针。
  • 拿不准就按值返回，别为了省一次拷贝埋一颗随机崩溃的雷。

记住这句就行：返回引用之前先问一句——这口箱子，函数结束后还在不在？

术语对照：这种情况正式叫「悬空引用（dangling reference）」，属于「未定义行为（UB）」。

术语小抄：教材、报错、面试，说的都是这些正式名字

看教材、看编译器报错、面试时用的都是上面的正式名称，遇到术语就翻译回这套比喻——箱子、纸条、门牌号、封条、冲水、谁家的。

error: binding reference of type 'int&' to 'const int' discards qualifiers

逐词对一下：binding 是"往上贴"，reference 是"那张纸条"，discards qualifiers 是"把 const 这张封条给撕了"。

这是在说"你想给一个承诺不改的东西贴一张能改的纸条，不行"。

比如写 const int a = 10; int& r = a; 就会撞上这条报错：a 已经被封条封住了，不许再贴一张能改的纸条。

Day 2 · 内存、类型与函数规则

还是箱子那套比喻。Day 2 多了一个新东西：门牌号能自己申请、自己归还（new / delete）。每张卡同样按「动机 → 比方 → 例子和输出 → 常错 → 结论」走。

7new / delete：租房子和退房子必须对上

没有它会怎样：栈上数组的大小必须编译时定死，数据一多就爆栈；想按运行时的数量申请，只能找堆。new 是租一间房、拿到门牌号，delete 是退租；怎么租的就怎么退，这是唯一死规矩。

int* p = new int;      // 租一间房，门牌号交给 p
*p = 42;
std::cout << *p;       // 输出：42
delete p;              // 退租：一间房就用 delete
p = nullptr;           // 退完把号码划掉

int* arr = new int[10]; // 租一排十间房
arr[0] = 1;
std::cout << arr[0];    // 输出：1
delete[] arr;           // 退一排：必须用带方括号的 delete[]
arr = nullptr;

// int* q = new int;
// free(q);             // 错：new 的房不能找 free 退
  • 配对表只有两行：new ↔ delete，new[] ↔ delete[]。拿错钥匙属于未定义行为，常见表现是当场崩溃。
  • 退完不置空 = 悬垂指针：号码还捏在手里，再照着找过去就是开一扇已经不属于你的门。
  • delete nullptr 是安全的：什么都不做，所以置空后重复退也不会出事。

记住这句就行：谁 new 的谁 delete，怎么借的怎么还，退完立刻把号码划掉。

术语对照：这叫「动态内存分配与释放」，退完不置空再用叫「悬垂指针（dangling pointer）」，同一块退两次叫「double free」。

8nullptr：一张写着"没有门牌号"的卡片

没有它会怎样：C 里 NULL 本质就是数字 0，遇到重载或模板，编译器分不清你要"整数 0"还是"空指针"。nullptr 是一张写着"没有门牌号"的专用卡片，只认指针，不认整数。

int* p = nullptr;              // 空指针的标准写法（C++11 起）
std::cout << (p == nullptr);   // 输出：1

int* q = new int(7);
delete q;
q = nullptr;                   // 退完立刻划掉号码，防野指针

// int x = nullptr;            // 编译报错：error: cannot convert 'std::nullptr_t' to 'int'
// void f(int); void f(char*);
// f(NULL);                    // 二义性：两个版本都能匹配，编译器不替你猜
  • 是啥：C++11 引入的空指针字面量，类型是 std::nullptr_t，能隐式转成任何指针类型。
  • 干嘛用：初始化、判空、delete 之后立刻置空防野指针。
  • 和 NULL 的本质区别：NULL 是 0 的宏，模板还会把它推导成 int；nullptr 能转任意指针，但不能转成整数（上面那条报错就是证据）。
  • 最容易踩的坑：nullptr 是 C++ 的东西，.c 文件里没有（那里只能写 NULL 或 0）。Keil 工程 .c/.cpp 混着写，最容易在这报错。
  • 嵌入式影响：解引用空指针在 STM32 上等于读地址 0，直接进 HardFault。HAL 库里到处写 if (p == NULL) return HAL_ERROR; 就是这个原因。

记住这句就行：.cpp 里判空一律写 nullptr，.c 里只能写 NULL 或 0。

术语对照：nullptr（空指针字面量）、NULL（C 里的 0 宏）、std::nullptr_t（它的类型）、野指针（dangling pointer）。

9struct 加强：箱子自己也会干活了

没有它会怎样：C 里数据和函数分家，函数只能叫 Point_sum(&p)，点一多就分不清谁管谁。C++ 的 struct 能把函数装进去，p.sum() 一眼看出这是 p 的事——这就是通往"类"的那级台阶。

struct Point {
    int x, y;
    int sum() { return x + y; }   // 函数直接用自己的 x、y
};

int main() {
    Point p;              // 不用写 struct Point p;
    p.x = 3;
    p.y = 4;
    std::cout << p.sum(); // 输出：7
}
  • p.sum() 读作"让 p 这口箱子干 sum 这件事"：点左边是箱子，右边是动作。
  • 写 struct Point p; 也能编译，那是 C 的习惯；C++ 里直接把 Point 当类型名用。
  • struct 和 class 只差默认权限；struct 默认公开，正好接上 Day 3 卡 19。

记住这句就行：C++ 的 struct 是"带动作的箱子"，定义变量不用再带 struct。

术语对照：结构体里的函数叫「成员函数（member function）」，p.sum() 这种写法叫「成员访问」，把数据和操作它的函数放进同一个盒子叫「封装」。

10bool：只有"是"和"否"两个格子

没有它会怎样：C 里用 int 装真假，0、1、-1 混着用，读代码先得猜"这个 1 是数量还是真"。bool 只有 true/false，意图一眼看懂，占 1 个字节。

bool ok = true;
bool err = false;
std::cout << ok;       // 输出：1（true 当数字用就是 1）
std::cout << err;      // 输出：0

int n = true;          // n 变成 1
bool flag = 5;         // 只给警告，非 0 都算 true —— 别这么写

if (ok) { /* 直接当条件用，不用写 ok == true */ }
  • 它是 1 字节，不是 1 位。8 个 bool 就是 8 字节，别指望靠它省 RAM；真要按位省，得自己用位操作（Day 2 卡 16）。
  • 数字变 bool 只认"是不是 0"：0 是 false，非 0 都是 true。
  • 写 if (ok) 就够了；if (ok == true) 是废话，还容易手滑写成赋值。

记住这句就行：bool 是"是/否"两个格子，true 当数字用等于 1，false 等于 0。

术语对照：正式叫「布尔类型（bool）」，true/false 叫「布尔字面量」，bool 变 int 这一步叫「整型提升」。

11const：贴了封条就不许改

没有它会怎样：100 这种"魔法数字"散落在十个文件里，改需求时漏一处就是一个 bug。const 给数字起名、加类型、上封条，改错地方编译器当场拦。

const int MAX = 100;
// MAX = 200;            // 编译报错：error: assignment of read-only variable 'MAX'

#define SIZE 10          // 老写法：纯文字替换，没有类型
const int size = 10;     // 新写法：有类型、有作用域，调试器看得见

const int table[] = {1, 2, 3};   // 配置表加 const，通常进 flash，不占 RAM
  • const 变量必须当场给值：const int a; 单独一句编译不过。
  • 嵌入式重点：全局 const 数组一般被放进 flash，RAM 里不占地方；把 const 去掉，它才会被搬进 RAM。
  • #define 出错时报错会指向替换后的怪代码；const 是真变量，报错直接指到名字。

记住这句就行：不想被改就贴封条；只读的大参数写 const T&；配置表加 const 省 RAM。

术语对照：const 修饰的变量叫「常量」，const T& 形参叫「常量引用」，放进 flash 的那块叫「只读数据段（.rodata）」。

12默认参数：只能从右往左连续给

没有它会怎样：串口 99% 的调用都是 8 数据位、1 停止位，每次全写又长又容易写错。默认参数让常用配置直接省略，只写和默认不一样的那几个。像点外卖默认不加香菜：没特别交代就按默认来，想换才开口。

void uart(int baud, int bits = 8, int stop = 1);  // 默认值写在声明里

uart(115200);        // bits=8，stop=1（最常用）
uart(115200, 7);     // bits=7，stop=1
// uart(115200, , 2);  // 错：中间不能空着跳过去

// void f(int a = 1, int b);
// 编译报错：error: default argument missing for parameter 2 of 'void f(int, int)'

// void uart(int baud, int bits = 8, int stop = 1) { }  // 定义里又写一遍
// 编译报错：error: default argument given for parameter 1 of 'void uart(int, int, int)'
  • 为什么必须从右往左：实参按位置填，中间空着编译器不知道给谁。
  • 只写一处：声明和定义都写会报"重定义默认参数"，习惯写在声明（头文件）里。
  • 和重载混着用最容易撞车，见下一张卡片。

记住这句就行：默认值从右边开始连着给，只写一处，中间不许跳。

术语对照：正式叫「默认参数（default argument）」，两个候选都能匹配的情况叫「二义性（ambiguous）」。

13函数重载：同名不同参数，别看返回值

没有它会怎样：C 里同一件事、不同类型得起 abs_i、abs_f 一堆名字，调用时还得记住用哪套。重载让同名函数按参数自动挑，返回值不参与挑。像同一个窗口办不同业务：递身份证办身份证、递驾照办驾照，窗口名字一样，看你递什么。

void f(int x)    { std::cout << "int\n"; }
void f(double x) { std::cout << "double\n"; }

f(1);      // 输出：int
f(1.0);    // 输出：double

// int f(int x);   // 编译报错：error: ambiguating new declaration of 'int f(int)'
                    // 只改返回值不算重载

void g(int x);
void g(int x, int y = 0);
// g(1);           // 二义性：两个版本都能匹配
  • 参数个数、类型、顺序，只要有一处不同就算重载；返回值不参与挑选，因为调用处看不见返回值。
  • f(1.0f) 会让编译器在 f(int) 和 f(double) 之间替你挑（float→double 是提升，转 int 是截断），不报错但你要知道它在挑。
  • 真撞上二义性，最省事的办法是改名字，别跟编译器较劲。

记住这句就行：重载看参数不看返回值；两个都能匹配就报二义性，改名字最省事。

术语对照：正式叫「函数重载（overload）」，两个候选都匹配叫「二义性调用（ambiguous call）」。

14volatile：告诉编译器"这个值会自己变"

没有它会怎样：中断把 flag 改成 1，编译器却不知道有人在外面改，把 while (!flag) 优化成死循环——程序"卡死"，而且一个错都不报。volatile 就是在说：这个值会自己变，每次都必须真去内存读。像有人在你背后偷偷改白板上的数字，你不每眼都去看，就永远读到旧的。

volatile unsigned int* const GPIOA_ODR =
        (volatile unsigned int*)0x40020014;   // 寄存器地址
*GPIOA_ODR |= (1u << 5);                    // 每次写都真的落到寄存器

volatile unsigned char flag = 0;   // 中断里会把它置 1

int main() {
    while (!flag) { }   // 加了 volatile：中断置 1 后循环退出
                        // 不加：-O2 下可能变成永远退不出的死循环
}
  • 这个例子要在板子/中断环境里跑；电脑上可以用 -O2 看反汇编验证，别指望它打印什么。
  • 三种必须加的场景：外设寄存器指针、中断与主循环共享的变量、DMA 收发的缓冲区。
  • 它只管"别优化"，不管"安不安全"。volatile int n; n++; 仍不是原子操作，中断同时改会丢数据，得关中断或用原子操作。
  • 可以跟 const 一起用：只读的状态寄存器就是 volatile const；普通局部变量别乱加，只会变慢。

记住这句就行：会被硬件或中断改的变量和寄存器指针，必须加 volatile；它挡的是编译器优化，不是并发。

术语对照：正式叫「volatile 限定符」，读作"易变的"；把地址写成指针叫「寄存器映射」，中断和主循环共用的变量叫「共享变量」。

15static：函数里的"记忆"，文件里的"私事"

没有它会怎样：想让函数记住"上次调到哪一步"，C 里只能用全局变量，结果全工程都能改它。函数里的 static 是只有这个函数能碰的"记忆"：只初始化一次，函数退出也不销毁。

void tick() {
    static int count = 0;   // 只初始化一次，下次调用接着上次的值
    count++;
    std::cout << count << '\n';
}
int main() { tick(); tick(); tick(); }
// 输出：
// 1
// 2
// 3

static void led_on() { /* ... */ }   // 只在本 .c 里能调用
static int s_err;                    // 其他文件链接不到
  • 函数内 static：适合计数器、状态机的上一步状态，不用把变量暴露成全局。
  • 文件作用域 static：嵌入式里常用来做"模块私有函数"，多个 .c 里同名也不冲突。
  • 初始化时机：比 main 还早；程序运行期间一直占着这块内存，不随函数退出释放。
  • 别写进头文件：每个包含它的 .c 都会各自复制一份，看着像同一个其实不是——这种错不报，最难查。

记住这句就行：static 在函数里是"记性"，在文件里是"私事"。

术语对照：这种"程序一直活着"的存储叫「静态存储期」；只在本文件可见叫「内部链接」，模块自己用的函数叫「模块私有函数」。

16位操作写寄存器：只动那一位，别把别的位冲掉

没有它会怎样：直接写 reg = 0x08 会把其他位一起清零，别的外设配置瞬间全丢。改寄存器只动目标位：置位 |=、清零 &= ~、翻转 ^=，判断用 &。寄存器就像一排并排的开关，只能拨你要的那一个，别把总闸拉下来。

#define BIT(n) (1u << (n))

unsigned int reg = 0;
reg |=  BIT(3);   std::cout << reg;   // 输出：8（第 3 位变 1）
reg &= ~BIT(3);   std::cout << reg;   // 输出：0（第 3 位变 0）
reg ^=  BIT(3);   std::cout << reg;   // 输出：8（翻转）

if (reg & BIT(3)) { }   // 判断第 3 位是不是 1

// 改多位：先把这几位清零，再写新值
reg = (reg & ~(0x3u << 4)) | (0x2u << 4);
  • 1 << 31 的坑：有符号 int 左移到最高位是未定义行为，写 1u << 31 才稳。
  • 读-改-写不是原子的：主循环和中断同时改同一个寄存器，可能互相覆盖。要么关中断，要么用硬件的置位/清除寄存器。
  • 别用魔法数字：地址和位号用宏或头文件定义，换板子只改一处。
  • 位域（bit-field） 每个编译器排布可能不同，通信协议里别用，寄存器操作优先用宏。

记住这句就行：改一位用 |= 和 &= ~，别直接赋值，否则会把旁边的位一起冲掉。

术语对照：那串用来挑位的 0/1 叫「位掩码（mask）」，|= 叫「置位」，&= ~ 叫「清零」，读一遍再写回去叫「读-改-写」。

Day 3 · 类、构造与析构

今天的主线：把「数据」和「操作」捆成一个对象，再搞清楚对象出生（构造）和退房（析构）时自动发生什么。每张卡都会打出真实输出，照着顺序看。

17面向过程 vs 面向对象：自己造车，还是找专业的人

没有它会怎样：外设一多，数据散在一堆全局变量里、函数名越叫越长，改一处要翻遍文件。面向过程是自己从挖矿开始一步步干；面向对象是把活儿拆给发动机厂、轮胎厂，自己只定接口、验收。

// C 的写法：数据和操作分家，函数名得自己带前缀
struct CPerson { const char* name; int age; };
void c_eat(CPerson* p) { std::cout << p->name << " 吃饭\n"; }

// C++ 的写法：数据和操作捆进一个类
class Person {
public:
    const char* name;
    int age;
    void eat() { std::cout << name << " 吃饭\n"; }  // 行为跟着数据走
};

int main() {
    CPerson a{"小明", 20};
    c_eat(&a);        // 输出：小明 吃饭
    Person b{"小红", 18};
    b.eat();          // 输出：小红 吃饭
}

// c_eat(&b);    // 编译报错：error: cannot convert 'Person*' to 'CPerson*'
                 // 两套写法类型不通用，得按对象那一套来
  • 面向过程的特点：开发慢一点，但性能高、看得见每一步。小项目、单片机裸机程序，很多时候这么写最合适。
  • 面向对象的特点：开发快、好扩展，代价是多一点间接开销。十几个外设模块、状态一堆时，用它更好管。
  • 不是谁高级谁低级：它们是两套拆问题的办法。嵌入式里常见的是"哪块合适用哪套"，而不是全盘二选一。

记住这句就行：小项目过程式够用；模块多、状态多，就用类把数据和操作捆一起。

术语对照：正式叫「面向过程（POP）」和「面向对象（OOP）」，三大特点是封装、继承、多态。

18封装：把东西装进盒子，再上一把锁

没有它会怎样：所有成员都敞开，谁都能写 user.id = -999;，等发现数据不对，全工程几百处赋值根本查不出是谁干的。封装 = 把东西装进盒子，再上一把锁，只留几扇门。

class User {
    int id;                                   // 默认 private：外面碰不到
public:
    void setId(int v) { if (v > 0) id = v; }  // 门：还能顺手检查合法性
    int  getId() const { return id; }
};

int main() {
    User u;
    // u.id = -999;      // 编译报错：error: 'int User::id' is private within this context
    u.setId(100);
    std::cout << u.getId();   // 输出：100
    u.setId(-5);              // 被门拦住，id 不变
    std::cout << u.getId();   // 输出：100
}
  • public：外面能直接用；private：只有类自己的成员函数能用；protected：类和子类能用，没继承时等同 private。
  • 为什么属性要私有：不是防同事，是防"以后改内部结构时，外面几百处代码跟着崩"。
  • 类内部不分权限：同一个类的成员函数之间，private 成员照样访问；权限只在类外才有意义。

记住这句就行：属性私有、接口公开；以后改内部实现，外面用的人不用跟着改。

术语对照：这套做法叫「封装（encapsulation）」，改属性的函数叫 setter，读属性的叫 getter。

19class 与 struct：只差一个默认权限

没有它会怎样：C 的 struct 默认全公开，照搬到 C++ 里如果也敞开，封装就白做了。C++ 保留 struct 是为了兼容 C（默认 public），新写的类用 class（默认 private）——两个关键字只差这一条默认权限。

class User {
    int id;                 // 没写权限：class 默认 private
public:
    void setId(int mid);
    int  getId();
};

// 类外实现：函数名前必须加 类名::
void User::setId(int mid) { id = mid; }
int  User::getId() { return id; }

struct Point {
    int x, y;               // 没写权限：struct 默认 public
};

int main() {
    Point p{3, 4};
    std::cout << p.x + p.y;  // 输出：7
}

// void setId(int mid) { id = mid; }   // 忘了 User::
// 编译报错：error: 'id' was not declared in this scope
  • 忘了 User::：写出来的就是普通全局函数，碰不到类的成员；编译器会在 id 这一行报"未声明"。
  • 工程里的常规拆法：Demo.h 放类声明（加 #pragma once），Demo.cpp 写 Demo:: 实现，main.cpp 只 include 头文件。
  • 为什么分文件：改实现不用动头文件，别人也不用看见你的实现细节。

记住这句就行：class 默认上锁，struct 默认敞开；类外实现别忘 类名::。

术语对照：:: 叫「作用域解析运算符」，读作"谁家的"；#pragma once 是「头文件保护」，防止同一个头文件被重复展开。

20构造函数：对象一出生就自动跑的那段

没有它会怎样：C 里 struct Point p; 之后 x、y 是垃圾值，每个对象创建后都得手动赋值，忘一个就带着随机数跑。构造函数就是对象一出厂自动执行的出厂设置：名字和类名一样、没有返回值、可以重载。

class Demo {
    int a;
public:
    Demo()      { a = 0; std::cout << "无参构造\n"; }
    Demo(int v) { a = v; std::cout << "有参构造 " << a << "\n"; }
};

int main() {
    Demo x;        // 输出：无参构造
    Demo y(10);    // 输出：有参构造 10
    Demo z = 30;   // 输出：有参构造 30（单参隐式转换，卡 25 讲为什么危险）
}
// 为什么是这个顺序：main 按书写顺序执行，一个对象触发一次构造

// 只写了 Demo(int) 却想写 Demo d;
// 编译报错：error: no matching function for call to 'Demo::Demo()'
  • 默认构造会失效：只要你自己写了任何一个构造函数，编译器就不再送你那个空的无参构造。
  • 所以两个都写：无参和有参都实现，别人写 Demo d; 才不会突然编译不过（就是上面那条报错）。
  • 匿名对象：Demo(); 只是临时造一个，分号一到就析构，不会留在栈上（卡 23 讲析构）。

记住这句就行：自己写了构造函数，编译器就不再免费送无参构造。

术语对照：正式叫「构造函数（constructor）」，没参数的叫「默认构造函数」，同名不同参数叫「重载」。

21拷贝构造：拿一个旧对象，造一个新对象

没有它会怎样：编译器会白送一个"逐成员抄一遍"的拷贝构造，普通成员够用；但它只在用旧对象造新对象时被调用，很多人以为赋值也会走它。拷贝构造 = 照着图纸另盖一栋一模一样的房子，不是同一栋房挂两个门牌。

class Demo {
public:
    int a;
    Demo(int v) { a = v; std::cout << "有参构造 a=" << a << "\n"; }
    Demo(const Demo& o) { a = o.a; std::cout << "拷贝构造 a=" << a << "\n"; }
    ~Demo() { std::cout << "析构 a=" << a << "\n"; }
};

int main() {
    Demo x(1);          // 输出：有参构造 a=1
    {
        Demo y = x;     // 输出：拷贝构造 a=1（旧对象造新对象）
    }                   // 输出：析构 a=1（y 先走）
    Demo z(x);          // 输出：拷贝构造 a=1
    Demo& r = x;        // 不打印：只是第二张纸条，不是新对象
}                       // 输出：析构 a=1（z 走）、析构 a=1（x 走）

// Demo(Demo o) { }    // 编译报错：error: invalid constructor; you probably meant 'Demo (const Demo&)'
  • 三种常见时机：用旧对象初始化新对象、对象按值传参、对象按值返回（最后一种编译器常会优化掉）。
  • 先定义再赋值不是拷贝构造：Demo y; y = x; 走的是赋值运算，不会打印"拷贝构造"。
  • 参数必须传引用：写成 Demo(Demo obj) 会为了传参再造一个对象，无限套娃，编译器直接拦。

记住这句就行：旧对象初始化新对象才叫拷贝构造；起别名、赋值都不是。

术语对照：正式叫「拷贝构造函数（copy constructor）」，也叫复制构造函数；参数写成 const 类名& 是标准姿势。

22浅拷贝与深拷贝：指针成员的生死问题

没有它会怎样：默认拷贝是浅拷贝——指针成员只抄地址，两个对象共用一块堆。像两个人只有一把钥匙：一个人退租把房退了，另一个人手里的钥匙就成了废铁。表现是改一个动两个，析构时二次释放直接崩。

class Demo {
    char* name;
public:
    Demo(const char* s) {
        name = new char[strlen(s) + 1];
        strcpy(name, s);
        std::cout << "申请 " << name << "\n";
    }
    Demo(const Demo& o) {                       // 深拷贝：自己再租一块
        name = new char[strlen(o.name) + 1];
        strcpy(name, o.name);
        std::cout << "深拷贝 " << name << "\n";
    }
    ~Demo() { std::cout << "释放 " << name << "\n"; delete[] name; }
};

int main() {
    Demo a("Tom");   // 输出：申请 Tom
    Demo b = a;      // 输出：深拷贝 Tom
}
// 输出：释放 Tom
//       释放 Tom   ← 两块不同的内存，各释放一次，安全

// 如果没写深拷贝：两个 name 指向同一块
// 第二次释放会崩：free(): double free detected in tcache 2
  • 浅拷贝的后果：改 b.name 连带改掉 a.name；两个析构各释放一次同一块内存，程序直接崩。
  • 深拷贝的做法：先按对方长度 new 一块新的，再 strcpy 过来。
  • 顺手纠坑：new char[...] 必须配 delete[]，不是 delete；数组和单个对象是两本账。
  • 三法则：类里有指针，拷贝构造、拷贝赋值、析构一般都要自己写。

记住这句就行：类里有指针，拷贝必须自己申请新内存，析构必须自己释放。

术语对照：只抄地址叫「浅拷贝（shallow copy）」，重新开一块叫「深拷贝（deep copy）」；同一块内存释放两次叫「双重释放（double free）」。

23析构函数：对象退房前自动收拾

没有它会怎样：类里有 new 出来的内存，对象销毁时没人还，跑久了 RAM 被吃光——单片机一共就几十 KB，最先出事。析构函数就是退房前自动收拾行李、交钥匙：~类名()，无返回值、不能写 void、不能带参数、不能重载。

class Demo {
public:
    const char* name;
    Demo(const char* n) : name(n) { std::cout << "出生 " << name << "\n"; }
    ~Demo() { std::cout << "退房 " << name << "\n"; }
};

int main() {
    Demo a("a");       // 输出：出生 a
    {
        Demo b("b");   // 输出：出生 b
        Demo c("c");   // 输出：出生 c
    }                  // 输出：退房 c、退房 b（后进先出，像叠盘子）
    Demo d("d");       // 输出：出生 d
}                      // 输出：退房 d、退房 a（栈清空）

// void ~Demo() { }    // 编译报错：error: return type specification for destructor invalid
// ~Demo(int x) { }    // 编译报错：error: destructors may not have parameters
  • 栈上的顺序：同一作用域后构造的先析构，先构造的后析构；析构顺序永远和构造相反。
  • 全局对象：main 结束后析构，一般也后进先出，但不同编译器可能略有差别，别依赖它。
  • 什么时候必须写：类里有 new 出来的指针成员；不写就是内存泄漏——对象没了，堆那块还在。
  • 没有指针就别硬写：普通类用编译器默认的空析构就够了。

记住这句就行：谁 new 的谁 delete，析构函数就是对象的退房手续。

术语对照：正式叫「析构函数（destructor）」；对象离开 {} 叫「出作用域」；new 了没还叫「内存泄漏（memory leak）」。

24初始化列表：成员对象的"有参构造"只能在这儿点

没有它会怎样：成员本身是个对象、又只有带参构造时，函数体里再赋值已经晚了——编译器会先要求它"默认出生"，没有默认构造就直接编译不过。初始化列表 : a(mA), b(mB) 就是盖房子前先按图纸订好材料，而不是先随便盖再拆了重装。

class Part {
public:
    Part(int id) { std::cout << "Part 构造 " << id << "\n"; }
    ~Part() { std::cout << "Part 析构\n"; }
};

class Car {
    Part engine;   // 声明在前：先构造
    Part wheel;    // 声明在后：后构造
public:
    Car() : wheel(2), engine(1) { std::cout << "Car 函数体\n"; }
};

int main() { Car c; }
// 输出：Part 构造 1
//       Part 构造 2      ← 按声明顺序，不按列表书写顺序
//       Car 函数体
//       Part 析构
//       Part 析构        ← 析构顺序和构造相反

// 成员只有 Part(int)，却想在函数体里赋值：
// class Car { Part p; public: Car() { p = Part(1); } };
// 编译报错：error: no matching function for call to 'Part::Part()'
  • 构造顺序：先按成员在类里的定义顺序构造，和初始化列表的书写顺序无关；最后才执行自己的函数体。
  • 析构顺序：和构造相反，先析构自己，再析构成员对象。
  • const 成员和引用成员：也必须在初始化列表里给值，函数体里赋值来不及。

记住这句就行：成员对象的有参构造只能在初始化列表里点，函数体里赋值已经晚了。

术语对照：正式叫「初始化列表（member initializer list）」；类里的对象成员叫「对象成员 / 成员对象」。

25explicit 与默认成员函数：今天最容易踩的四个坑

没有它会怎样：单参构造默认允许隐式转换，Dept d = 100; 这种像赋值的写法、甚至函数传参 show(100) 都会偷偷造对象，写错了编译器还帮你圆。explicit 就是门禁必须刷卡：想进门，老老实实写 Dept(100)。

class Dept {
public:
    explicit Dept(int id) { did = id; }
    int did;
};

void show(Dept d) { std::cout << d.did << "\n"; }

int main() {
    show(Dept(100));   // 输出：100（明确造对象）
    // show(100);      // 编译报错：error: could not convert '100' from 'int' to 'Dept'
    // Dept d = 100;   // 同样被挡住
}
  • 坑 1：默认权限 —— class 不写 public 就全是 private，外面 user.id = 1; 直接编译不过（卡 19）。
  • 坑 2：默认构造失效 —— 自己写了有参构造，Demo d; 就编不过；无参构造要自己补（卡 20）。
  • 坑 3：浅拷贝 —— 有指针成员还用默认拷贝，轻则改一个动两个，重则双重释放崩溃（卡 22）。
  • 坑 4：new / delete 配错 —— new[] 配 delete[]，new 配 delete（卡 7）。
  • 默认成员函数：编译器白送无参构造、拷贝构造、拷贝赋值、析构；老话「三法则」指拷贝构造、拷贝赋值、析构这三个要一起写。你一旦自己写了拷贝构造，默认的无参构造也就不再送了。

记住这句就行：单参构造加 explicit，指针成员自己写拷贝和析构，能挡掉今天一半的坑。

术语对照：explicit 读作"显式的"，挡掉的叫「隐式转换（implicit conversion）」；编译器白送的这几个合称「默认成员函数」。

今天这 5 个面试题，先用人话过一遍

① 面向过程和面向对象有什么区别？过程式按步骤拆，性能高、开发慢；OOP 按对象和责任拆，开发快、好扩展，代价是一点间接开销。

② 三大特征是什么？封装（数据和操作捆一起、上权限）、继承（复用父类）、多态（同一个接口，不同对象有不同实现）。今天只要求把封装讲清楚。

③ 构造函数和析构函数干什么？构造：对象出生时自动初始化成员；析构：对象退房前自动清理，尤其是把 new 出来的内存还掉。

④ public / protected / private 区别？public 外面能用；private 只有类自己能用；protected 类和子类能用，没继承时等同 private。

⑤ 浅拷贝和深拷贝？浅拷贝只抄指针地址，两个对象共用一块堆，容易双重释放；深拷贝重新申请一块，各管各的。

今天先把「封装 + 构造 + 析构 + 深拷贝」这四件事写熟，继承和多态等下一课再展开，现在碰只会混。
