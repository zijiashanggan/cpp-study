Day 1 · 引用这条主线

每个卡片一句话结论 + 最小示例。先看结论，再读代码，不要背。

1引用：同一个箱子又贴了一张纸条

int& r = a; 不是在旁边又造一个箱子，而是给 a 那个箱子再贴一张写着 r 的纸条。撕哪张纸条，箱子都还是同一个。

int a = 10;      // 造一个箱子，贴上纸条 a，里面放 10
int& r = a;       // 给同一个箱子再贴一张纸条 r

r = 99;          // 顺着 r 找到箱子，把里面的 10 换成 99
                 // 所以 a 也是 99 —— 本来就是同一个箱子

int b = 20;      // 另一个箱子，里面放 20
r = b;           // 这句是"把 b 里的 20 倒进 r 管的那个箱子"，
                 // 不是"把 r 的纸条撕下来贴到 b 上"
                 // 结果：a = 20，b 还是 20
  • 必须当场贴：写 int& r; 等于说"我要贴张纸条"，却没说贴哪个箱子，编译器不知道贴哪儿，直接不给你过。
  • 贴了撕不掉：r = b; 是把 b 里的东西倒进 a，纸条原地不动。真想换箱子，只能改用门牌号（指针）。
  • 不能对着空气贴：没有"空引用"这回事。要表示"可能没有箱子"，得用门牌号（指针）。

记住这句就行：引用不是新箱子，是同一口箱子上的第二张纸条。

术语对照：正式叫「引用（reference）」，教材上的准确说法是"变量的别名，不额外占用存储空间"。

2三种 swap：抄一份 / 递门牌号 / 递原件

想让函数真的把外面两个箱子的东西互换，就得把原件递进去；抄一份给他，他改得再热闹，你的箱子也没动一下。

// ① 抄一份给他改
void swap1(int x, int y) { int t = x; x = y; y = t; }
// 调用 swap1(m, n);  —— 复印两份递进去
// 里面换的是复印件，函数一结束复印件就扔了，m、n 一点没变

// ② 递门牌号：他得照着号码找过去、开门，才能搬东西
void swap2(int* x, int* y) {
    if (x == nullptr || y == nullptr) return; // 先问一句：号码是不是空的
    int t = *x; *x = *y; *y = t;              // 照着门牌号找过去开门
}
// 调用 swap2(&m, &n);  —— 得自己先抄两个门牌号

// ③ 递原件：拿到的是同一口箱子，直接倒腾
void swap3(int& x, int& y) { int t = x; x = y; y = t; }
// 调用 swap3(m, n);   —— 跟传普通变量一样，最省事
  • 抄一份（值传递）：改的是复印件，外面毫无变化。
  • 递门牌号（指针）：能改到外面，但调用要写 &，函数里要写 *，还得先问号码空不空。
  • 递原件（引用）：能改到外面，写法和普通变量一模一样，也没有"空"的问题。
  • 那什么时候还得用门牌号？比如读写寄存器：硬件那边根本没有箱子给你贴纸条，只有一个地址（像 0x40020000 这种），这时候只能拿门牌号去找。

记住这句就行：互换两个变量直接写引用版，别自己折腾门牌号。

术语对照：这三个版本依次叫「值传递」「地址传递（指针）」「引用传递（pass by reference）」。

3const T&：把原件递给他看，但不许改

传一大串字符这种大东西，复印一份太费劲。const 类型& 就是把原件递过去让他看，const 是贴在上面的封条，谁都不许动。

void show(const std::string& s) {  // 递原件 + 贴封条
    // s += "!";     // 想改？封条拦着，编译直接报错
    std::cout << s;   // 只能看
}

show(name);          // 没有复印，直接把 name 那口箱子递过去

const int& r = 10;   // 可以：给 10 这个临时箱子贴封条，再贴纸条
// int& r = 10;      // 不行：普通纸条不许贴到临时箱子上
  • 只写 std::string s：每次调用都要复印一整串字符，又慢又占地方。
  • 加引用但不加 const：不复印了，可函数里能顺手把你的东西改了，很危险。
  • 加 const：既不复印，也改不了——两头都占到。

记住这句就行：只看看、不打算改的大东西，参数就写成 const 类型&。

术语对照：正式叫「常量引用」，作用是不拷贝、不可修改，常用于函数形参。

4cout、endl、::：箭头、"冲水"和"谁家的"

cout << 的箭头朝右，把东西塞进屏幕；endl 是换行 + 冲水，串口想快就用 '\n'；:: 读作"谁家的"。

int a = 0;
std::cout << "请输入：";      // 箭头朝右：把字塞进屏幕
std::cin  >> a;               // 箭头朝左：把键盘敲的塞进箱子 a

std::cout << a << '\n';        // 只换行，不冲水 —— 快
std::cout << a << std::endl;    // 换行 + 冲水，马上送出去 —— 慢一点
  • endl 是换行 + 冲水：冲水就是把攒在管子里的字立刻推出去；'\n' 只换行，攒够了一起走。
  • 串口打印几十行时，一行冲一次水就得等一次硬件，明显拖时间，所以用 '\n'。
  • :: 读作"谁家的"：std::cout 是标准库这家的 cout；只写一个 ::a 是"全局那个 a"，不属于任何一家。
  • 有了"谁家的"，两个地方都叫 a 也能分清，不会打架。

记住这句就行：箭头朝哪儿东西就往哪儿走；endl 多了个冲水；:: 就是在说"谁家的"。

术语对照：std::cout 是「标准输出流对象」，endl 是「换行并刷新缓冲区」，:: 是「作用域解析运算符」。

5命名空间：给名字加个"谁家的"

就是给名字分个家，防止撞名。写全名最保险；using namespace 把人家的东西全搬进来，最容易撞；using A::a 只搬一个。

namespace A { int a = 1; int b = 2; }

A::a = 10;           // 写全名：A 家的 a，最保险
using namespace A;   // 把 A 家所有东西都搬进来：省事，但容易撞名
using A::a;          // 只搬 a 这一个：b 还得写 A::b

namespace { int x; } // 没名字的家：只在这个文件里看得见（效果跟加 static 一样）

记住这句就行：名字撞了就写 :: 说清楚是谁家的。

术语对照：正式叫「命名空间（namespace）」，没名字的那个用「内部链接」来描述。

6返回引用：别把拆掉的房子的门牌号给别人

函数里临时造的箱子，函数一结束就拆了。把它的地址交出去，别人拿着号码去开门——门还在不在，全看运气。

int g = 0;
int& getG() { return g; }        // 全局的箱子一直在，安全

int& bad() { int x = 1; return x; }  // x 是函数里的一次性箱子
                                     // 函数一结束就拆了，地址作废

void fill(int& out) { out = 42; }    // 调用者把自己的箱子递进来，安全

static int s = 5;                    // 加了 static 的箱子，程序跑完才没
int& getS() { return s; }            // 也安全
  • 能用的只有三种：全局的箱子、加了 static 的箱子、调用者自己递进来的箱子。
  • 写错了不一定马上崩，可能这次刚好没被别的东西盖住，看着"还能用"——换台机器就说不准了。

记住这句就行：返回引用之前先问一句——这口箱子，函数结束后还在不在？

术语对照：这种情况正式叫「悬空引用（dangling reference）」，属于「未定义行为（UB）」。

术语小抄：教材、报错、面试，说的都是这些正式名字

看教材、看编译器报错、面试时用的都是上面的正式名称，遇到术语就翻译回这套比喻——箱子、纸条、门牌号、封条、冲水、谁家的。

error: binding reference of type 'int&' to 'const int' discards qualifiers

逐词对一下：binding 是"往上贴"，reference 是"那张纸条"，discards qualifiers 是"把 const 这张封条给撕了"。

这是在说"你想给一个承诺不改的东西贴一张能改的纸条，不行"。

比如写 const int a = 10; int& r = a; 就会撞上这条报错：a 已经被封条封住了，不许再贴一张能改的纸条。

Day 2 · 内存、类型与函数规则

还是箱子那套比喻。Day 2 多了一个新东西：门牌号能自己申请、自己归还（new / delete）。

7new / delete：租房子和退房子必须对上

new 是"租一间房，拿到门牌号"，delete 是"退租"。怎么租的就怎么退——这是唯一一条死规矩。

int* p = new int;      // 租一间房，门牌号交给 p
*p = 42;               // 照着门牌号进去，放 42
delete p;              // 退租：一间房就用 delete
p = nullptr;           // 退完把号码划掉，免得以后误开

int* arr = new int[10]; // 租一排十间房
delete[] arr;           // 退一排，必须用带方括号的 delete[]
arr = nullptr;

// int* q = new int;
// free(q);              // 错：new 的房不能找 free 退
  • 配对表只有两行：new ↔ delete，new[] ↔ delete[]。拿错钥匙，后果没人保证。
  • delete p; 只是把房退了，门牌号还捏在手里。这时再照着它找过去，就是开一扇已经不属于你的门，所以退完立刻置空。
  • delete nullptr; 什么都不做，是安全的。所以置空以后重复退也不会出事。

记住这句就行：谁 new 的谁 delete，怎么借的怎么还，退完立刻把号码划掉。

术语对照：这叫「动态内存分配与释放」，退完不置空再用叫「悬垂指针（dangling pointer）」，同一块退两次叫「double free」。

8struct 加强：箱子自己也会干活了

C++ 的结构体不只是"装几个数的盒子"，里面还能写函数；定义变量时连 struct 都不用写。这就是通往"类"的那级台阶。

struct Point {
    int x;
    int y;
    int sum() { return x + y; }   // 结构体里可以写函数
};

Point p;              // 不用写 struct Point p;
p.x = 3;
p.y = 4;
std::cout << p.sum(); // 输出 7，函数直接用里面的 x、y
  • p.sum() 读作"让 p 这口箱子干 sum 这件事"，点左边是箱子，右边是动作，函数里能直接用 x、y。
  • 写 struct Point p; 也能编译，那是 C 的习惯；C++ 里直接把 Point 当类型名用。
  • struct 和 class 只差"默认开不开放给人看"，现在只要记住"struct 也能带函数"就够了。

记住这句就行：C++ 的 struct 是"带动作的箱子"，定义变量不用再带 struct。

术语对照：结构体里的函数叫「成员函数（member function）」，p.sum() 这种写法叫「成员访问」，把数据和操作它的函数放进同一个盒子叫「封装」。

9bool：只有"是"和"否"两个格子

bool 只有两个值：true 和 false，占 1 个字节，专门用来记"是/否"这种状态。

bool ok = true;        // 是
bool err = false;      // 否

std::cout << ok;       // 输出 1：true 当数字用就是 1
std::cout << err;      // 输出 0

int n = true;          // n 变成 1
bool flag = 5;         // 非 0 都算 true（会给你警告，别这么写）

if (ok) { /* 直接当条件用，不用写 ok == true */ }
  • 它是 1 字节，不是 1 位。8 个 bool 就是 8 字节，别指望靠它省 RAM；真要按位省，得自己用位操作。
  • 数字变 bool 只认"是不是 0"：0 是 false，非 0 都是 true。
  • 写 if (ok) 就够了；if (ok == true) 是废话，还容易手滑写成赋值。

记住这句就行：bool 是"是/否"两个格子，true 当数字用等于 1，false 等于 0。

术语对照：正式叫「布尔类型（bool）」，true/false 叫「布尔字面量」，bool 变 int 这一步叫「整型提升」。

10const：贴了封条就不许改

被 const 封住的箱子，谁都不能改；const T& 形参是"递原件看、不许改、也不复印"；const 有类型有作用域，比 #define 靠谱；配置表加 const 还能省 RAM。

const int MAX = 100;     // 贴上封条，后面谁改谁编译不过
// MAX = 200;            // 错：封条不是摆设

void show(const std::string& s);  // 不复印、不许改，大东西首选

#define SIZE 10          // 老写法：纯文字替换，没有类型
const int size = 10;     // 新写法：有类型、有作用域，能查错

const int table[] = {1, 2, 3};   // 配置表加 const，通常进 flash，不占 RAM
  • const 变量必须当场给值：const int a; 单独一句编译不过。
  • 嵌入式重点：全局的 const 数组一般被放进 flash，RAM 里就不占地方；把 const 去掉，它才会被搬进 RAM。
  • #define 是预处理阶段的文字替换，出错时报错信息会指向替换后的怪代码；const 是真变量，调试器也看得见。

记住这句就行：不想被改就贴封条；只读的大参数写 const T&；配置表加 const 省 RAM。

术语对照：const 修饰的变量叫「常量」，const T& 形参叫「常量引用」，放进 flash 的那块叫「只读数据段（.rodata）」。

11默认参数：只能从右往左连续给

默认值只能从最右边开始、一个接一个往左给，中间不能跳；声明和定义只能写一处；调用时省略的必须是靠右那几个。

void uart(int baud, int bits = 8, int stop = 1);  // 声明里给默认值

uart(115200);          // 行：bits=8，stop=1
uart(115200, 7);       // 行：bits=7，stop=1
// uart(115200, , 2);  // 错：中间不能空着跳过去

// void uart(int baud, int bits = 8, int stop = 1) { }  // 错：定义里又写一遍
  • 反例：void f(int a = 1, int b); 不合法——左边给了、右边没给，调用时编译器没法知道 b 填什么。
  • 默认值在声明和定义里只能挑一处写。写两处会报"重定义默认参数"，习惯上写在声明（头文件）里。
  • 和重载混着用最容易撞车，见下一张卡片。

记住这句就行：默认值从右边开始连着给，只写一处，中间不许跳。

术语对照：正式叫「默认参数（default argument）」，两个候选都能匹配的情况叫「二义性（ambiguous）」。

12函数重载：同名不同参数，别看返回值

同名、参数列表不同才算重载；只有返回值不同不算；两个版本都能匹配时，编译器不替你猜，直接报二义性。

void f(int x);        // 版本一：收整数
void f(double x);     // 版本二：收小数 —— 参数类型不同，算重载
// int  f(int x);     // 错：只改返回值，等于重复声明

f(1);                 // 挑版本一
f(1.0);               // 挑版本二

void g(int x);
void g(int x, int y = 0);   // 默认参数也能让 g(1) 对上两个版本
g(1);                       // 二义性：编译器不知道选谁
  • 参数个数、类型、顺序，只要有一处不同就算重载；返回值不参与挑选，因为调用处看不见返回值。
  • f(1.0f) 遇到 f(int) 和 f(double)：float 转 double 只是"提升"，转 int 要"截断"，编译器会挑 f(double)，这里不报错，但你要知道它在替你挑。
  • 真撞上二义性，最省事的办法是改名字，别跟编译器较劲。

记住这句就行：重载看参数不看返回值；两个都能匹配就报二义性，改名字最省事。

术语对照：正式叫「函数重载（overload）」，两个候选都匹配叫「二义性调用（ambiguous call）」。

怎么判断自己真的会了

  1. 关掉所有资料，从空白文件写出 swap，能编译能跑 —— 这才叫会。看着网页点头不算。
  2. 能看懂编译器的报错在说什么 —— 报错是最便宜的老师，它每次都直说哪一行不对。
  3. 能用人话把这件事讲给一个完全不懂的人听 —— 讲不清，就是还没懂。

提醒一句：网页刷题只能暴露盲点，不能替代动手。刷十轮，不如自己从零敲一遍。
